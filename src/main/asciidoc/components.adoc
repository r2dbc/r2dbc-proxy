[[components]]
= Components

This section explains the main components of R2DBC Proxy.

[[components_proxyconnectionfactory]]
== ProxyConnectionFactory

This is the entry point for creating a proxy `ConnectionFactory`.

The static `ProxyConnectionFactory#builder` method creates a `Builder` instance, which provides methods to
register listeners, configure the proxy, and generate a proxy `ConnectionFactory`.

[source,java]
----
ConnectionFactory original = ...

ConnectionFactory connectionFactory = ProxyConnectionFactory.builder(original)
    .onAfterQuery(queryInfo ->
        ...  // after-query callback logic
    )
    .onBeforeMethod(methodInfo ->
        ...  // before-method callback logic
    )
    .listener(...)  // add listener
    .build();
----

Alternatively, connection-factory discovery can create a proxy when the driver name is `proxy`.

[[components_proxyconfig]]
== ProxyConfig

`ProxyConfig` is the central configuration object for creating proxies.

A `ProxyConfig` instance holds proxy-related configuration, such as `ProxyExecutionListener`, `ProxyFactory`,
and `BindParameterConverter`. Any proxy objects created by a proxy `ConnectionFactory` share the same
`ProxyConfig` instance.

`ProxyConnectionFactory.Builder` automatically creates a `ProxyConfig` internally. It also accepts a custom
`ProxyConfig` when you need to override or extend the defaults.

[source,java]
----
ProxyConfig proxyConfig = ...

ConnectionFactory connectionFactory = ProxyConnectionFactory.builder(original, proxyConfig)
    ...
    .build();
----

[[components_proxyfactory]]
== ProxyFactory

`ProxyFactory` is the strategy interface used to create each proxy.

The default implementation, `JdkProxyFactory`, uses the JDK dynamic proxy to create proxy objects.

Providing a custom `ProxyFactory` allows a different proxy mechanism for constructing proxies. For example,
https://github.com/ttddyy/r2dbc-proxy-examples/blob/master/java-agent-example/common/src/main/java/io/r2dbc/examples/agent/ByteBuddyProxyFactory.java[here is a sample of using ByteBuddy for proxy creation].

When you provide a custom `ProxyFactory` implementation, `ProxyConfig` includes a method to register it.

[source,java]
----
ProxyFactory myProxyFactory = ...

ProxyConfig proxyConfig = ProxyConfig.builder()
    .proxyFactoryFactory(() -> myProxyFactory)  // add ProxyFactory supplier
    .build();
----

[[components_proxyexecutionlistener]]
== ProxyExecutionListener

`ProxyExecutionListener` is the root listener interface that defines callbacks for method invocation,
query execution, and query-result processing.

[source,java]
.Methods defined on ProxyExecutionListener
----
// invoked before any method on a proxy is called
void beforeMethod(MethodExecutionInfo executionInfo);

// invoked after any method on a proxy is called
void afterMethod(MethodExecutionInfo executionInfo);

// invoked before a query is executed
void beforeQuery(QueryExecutionInfo execInfo);

// invoked after a query is executed
void afterQuery(QueryExecutionInfo execInfo);

// invoked when each query result is processed (subscribed)
void eachQueryResult(QueryExecutionInfo execInfo);
----

Whenever a caller invokes a method on a proxy, it triggers the method callbacks `beforeMethod()` and
`afterMethod()`. They receive a `MethodExecutionInfo` parameter that contains contextual information about the
invoked method.

The query-execution methods, `Batch#execute()` and `Statement#execute()`, trigger the query callbacks
`beforeQuery()` and `afterQuery()`. (Specifically, they are invoked when the returned result publisher is
subscribed.) They receive a `QueryExecutionInfo` parameter that contains query details such as the SQL text,
bound parameter values, and query duration.

While processing a `Result`, `eachQueryResult()` is invoked for each mapped query result when `Result#map()`
is subscribed.

When you implement a custom `ProxyExecutionListener`, `ProxyConnectionFactory.Builder` provides a method to
register it. In addition, the builder offers convenience methods for registering ad-hoc listeners.

[source,java]
----
ConnectionFactory original = ...

ConnectionFactory connectionFactory = ProxyConnectionFactory.builder(original)
    .onAfterQuery(queryInfo ->
        ...  // after-query callback logic
    )
    .onBeforeMethod(methodInfo ->
        ...  // before-method callback logic
    )
    .listener(...)  // add listener
    .build();
----

[[components_proxymethodexecutionlistener]]
== ProxyMethodExecutionListener

`ProxyMethodExecutionListener` is an extension of `ProxyExecutionListener`. In addition to the methods
defined in `ProxyExecutionListener`, it adds explicit before/after methods for all methods on
`ConnectionFactory`, `Connection`, `Batch`, `Statement`, and `Result`.

Method names follow the pattern: _"[before|after]<MethodName>On<ClassName>"_.

For example, if you want to perform an action when a connection is created or closed:

[source,java]
----
public class ConnectionStartToEndListener implements ProxyMethodExecutionListener {

  @Override
  public void beforeCreateOnConnectionFactory(MethodExecutionInfo methodExecutionInfo) {
    // called before ConnectionFactory#create()
  }

  @Override
  public void afterCloseOnConnection(MethodExecutionInfo methodExecutionInfo) {
    // called after Connection#close()
  }
}
----

[[components_formatters]]
== Formatters

One common use of proxy listeners is logging contextual information. For example, when a query runs, a
listener can log the SQL text, parameters, success/failure state, execution time, and thread information.

Each callback method on `ProxyExecutionListener` receives contextual information such as `QueryExecutionInfo`
and `MethodExecutionInfo`. To create log entries, you transform this data into a `String`.

Formatter classes fill this gap. `QueryExecutionInfoFormatter` and `MethodExecutionInfoFormatter` are
available out of the box. They provide user-friendly conversion methods to transform all or selected parts of
`[Method|Query]ExecutionInfo` into a `String` using default or custom formatting.

[[components_formatters_queryexecutioninfoformatter]]
=== QueryExecutionInfoFormatter

This class converts `QueryExecutionInfo` to a `String`.

[source,java]
----
// convert all information
QueryExecutionInfoFormatter formatter = QueryExecutionInfoFormatter.showAll();
String str = formatter.format(queryExecutionInfo);

// convert it
String str = formatter.format(queryExecutionInfo);
----

[[components_formatters_methodexecutioninfoformatter]]
=== MethodExecutionInfoFormatter

This class converts `MethodExecutionInfo` to a `String`.

[source,java]
----
MethodExecutionInfoFormatter formatter = MethodExecutionInfoFormatter.withDefault();

// register as an ad-hoc listener
ProxyConnectionFactory.builder(connectionFactory)
  .onAfterMethod(execInfo ->
     System.out.println(formatter.format(execInfo)))  // convert and print to stdout
  .build();
----

[[components_formatters_customizing-formatter]]
=== Customizing Formatter

`QueryExecutionInfoFormatter` and `MethodExecutionInfoFormatter` internally hold a list of consumers and loop
through them to populate the output `StringBuilder`.

Each consumer converts a portion of the `[Query|Method]ExecutionInfo` into a `StringBuilder`.
Formatting is customizable by enabling or disabling built-in converters and by registering new consumers.

[source,java]
----
// customize conversion
QueryExecutionInfoFormatter formatter = new QueryExecutionInfoFormatter();
formatter.addConsumer((execInfo, sb) -> {
  sb.append("MY-QUERY-EXECUTION="); // add prefix
});
formatter.newLine();  // new line
formatter.showSuccess();
formatter.addConsumer((execInfo, sb) -> {
    // custom conversion
    sb.append("MY-ID=" + execInfo.getConnectionInfo().getConnectionId());
});
formatter.showQuery();

// convert it
String str = formatter.format(queryExecutionInfo);
----

[[components_bindparameterconverter]]
== BindParameterConverter

`BindParameterConverter` is a callback interface for bind-parameter operations such as `Statement#bind` and
`Statement#bindNull`.

The callback is invoked *before* the actual bind-parameter operation. It can modify the behavior of the
bind operation. For example, a converter can rewrite bind markers.

See more details in the
https://github.com/r2dbc/r2dbc-proxy/issues/26["gh-26: Proxy mechanism to support converting bind marker"] issue.

[[components_resultrowconverter]]
== ResultRowConverter

`ResultRowConverter` is a callback interface for result-row access via `Row#get`.

The callback is invoked *before* the actual `Row#get` call. It can alter the behavior of the invoked method.

To use the converter, register it with `ProxyConfig`.

[source,java]
----
ResultRowConverter converter = ...
ProxyConfig proxyConfig = ProxyConfig.builder().resultRowConverter(converter).build();

// create a proxy ConnectionFactory
ConnectionFactory proxy = ProxyConnectionFactory.builder(connectionFactory, proxyConfig).build();
----
